
# 🐍 GPT SNAKE — История разработки и правила сотрудничества

## 1. О проекте

GPT Snake — браузерная игра «Змейка», созданная совместно пользователем и ChatGPT.

**Цель:** сделать полноценную, интересную и визуально проработанную игру, которую можно запускать через GitHub Pages без установки дополнительных программ и зависимостей.

## 2. Технологические требования

- Основной файл проекта — `index.html`.
- HTML, CSS и JavaScript находятся в одном файле.
- Никаких обязательных внешних библиотек и зависимостей.
- Игра должна запускаться непосредственно в браузере.
- Совместимость с GitHub Pages.
- Сохранение рекордов и настроек через localStorage.
- Интерфейс должен полностью помещаться на одном экране браузера.
- Никакой вертикальной прокрутки страницы.
- Поддержка компьютеров и мобильных устройств.

## 3. Как мы работаем

Разработка ведётся в формате диалога между пользователем и ChatGPT.

### Роль пользователя

Пользователь выступает в роли заказчика и геймдизайнера.

Его задачи:
- Определять направление развития игры.
- Выбирать концепцию и референсы.
- Давать обратную связь по игровому процессу.
- Указывать на недостатки и непонятные механики.
- Формулировать новые требования.
- Принимать или отклонять предложенные решения.

Пользователь не обязан самостоятельно придумывать каждую механику или техническую реализацию.

### Роль ChatGPT

ChatGPT выступает в роли разработчика, технического специалиста и соавтора проекта.

Его задачи:
- Самостоятельно предлагать интересные механики.
- Принимать технические решения.
- Реализовывать игровой функционал.
- Продумывать интерфейс и визуальное оформление.
- Исправлять ошибки.
- Учитывать всю предыдущую обратную связь.
- Следить за совместимостью и производительностью.
- Предоставлять полностью готовый код.

ChatGPT не должен перекладывать технические решения на пользователя без необходимости.

## 4. История разработки

### Этап 1. Начало проекта

Пользователь предложил создать собственную версию «Змейки».

Пользователь делегировал творческие решения ChatGPT с пожеланием сделать игру действительно интересной и крутой.

Первоначальная концепция включала:
- Классическую змейку.
- Сбор еды и увеличение длины.
- Подсчёт очков.
- Сохранение рекорда.
- Паузу и перезапуск.
- Управление WASD и стрелками.
- Поддержку мобильных устройств.

### Этап 2. Выбор направления

Пользователь выбрал GPT Snake в качестве основы.

Было принято решение отказаться от сложной архитектуры и сделать автономную игру в одном HTML-файле.

ChatGPT подготовил концепцию VOID//SNAKE.

### Этап 3. Расширение игры

В последующих итерациях появились дополнительные игровые элементы:

- Classic — классический режим.
- Neon Rush — скоростной режим с ограничением времени.
- Portal — режим с порталами.
- Бонусы и усиления.
- Препятствия.
- Различные скины.
- Достижения.
- Система рекордов.
- Звуковые эффекты.
- CRT-визуальные эффекты.
- Боссы.
- Меню, пауза и перезапуск.
- Поддержка мобильного управления.

### Этап 4. Обратная связь и улучшения

Пользователь отдельно указал на несколько проблем и требований:

1. Необходимо добавить защиту от неправильной раскладки клавиатуры. WASD должны работать независимо от выбранной языковой раскладки.
2. В режиме Portal необходимо сделать понятнее механику синих шаров, которые влияют на время.
3. Все игровые особенности должны быть доступны с самого начала игры, а не открываться постепенно.
4. Необходимо сохранять компактность интерфейса: игра должна помещаться на одном экране без вертикальной прокрутки.

Эти замечания являются обязательными требованиями к дальнейшим версиям.

## 5. Принципы разработки

### Не упрощать без необходимости

Если пользователь просит улучшить игру, нельзя автоматически удалять существующие механики ради упрощения кода.

Все уже реализованные возможности должны сохраняться, если пользователь явно не попросил обратного.

### Учитывать обратную связь

Каждое замечание пользователя должно учитываться в следующей версии.

Нельзя исправлять одну проблему ценой появления нескольких других.

### Понятность игровых механик

Любая механика должна быть понятна игроку:
- Что делает объект.
- Как он влияет на игровой процесс.
- Как долго действует эффект.
- Какие последствия имеет взаимодействие с ним.

Необходимо использовать визуальные подсказки, описания и понятную обратную связь.

### Полнота функционала

Если пользователь просит, чтобы все особенности были доступны с самого начала, нельзя вводить искусственное постепенное открытие механик.

### Самостоятельность разработчика

ChatGPT должен проявлять инициативу, предлагать улучшения и самостоятельно принимать разумные технические решения.

Не нужно постоянно спрашивать пользователя о мелочах.

## 6. Правила взаимодействия и передачи кода

Это особенно важная часть проекта.

1. Пользователь предпочитает получать готовый код непосредственно в сообщении.
2. Не создавать файлы для скачивания, если пользователь прямо этого не попросил.
3. При необходимости предоставить полный `index.html`, готовый для копирования.
4. Не отправлять отдельные CSS-фрагменты вместо полного кода, если пользователь просит полноценную версию.
5. Не заставлять пользователя самостоятельно искать места для замены отдельных участков кода.
6. Не подключать GitHub и другие сервисы без необходимости.
7. Не утверждать, что файл создан или игра проверена, если это фактически не было сделано.
8. При обновлении проекта сохранять существующий функционал и исправлять обнаруженные ошибки.

## 7. Основной рабочий цикл

Разработка строится по следующему принципу:

1. Пользователь формулирует идею, замечание или пожелание.
2. ChatGPT анализирует текущую реализацию и требования.
3. ChatGPT самостоятельно выбирает способ реализации.
4. ChatGPT предоставляет готовый код.
5. Пользователь проверяет результат.
6. Пользователь сообщает, что понравилось и что необходимо исправить.
7. ChatGPT учитывает обратную связь и готовит следующую версию.

Цикл повторяется до достижения желаемого результата.

## 8. Текущий статус

Проект находится в стадии активной разработки.

Основное направление — развитие VOID//SNAKE с сохранением всех существующих механик.

Приоритетные задачи:
- Исправление управления WASD независимо от раскладки.
- Улучшение объяснения временных эффектов синих шаров в Portal.
- Доступность всех игровых механик с самого начала.
- Сохранение компактного интерфейса.
- Дальнейшее улучшение игрового процесса и визуальной составляющей.

---

## 9. Главное правило проекта

**Пользователь придумывает направление и оценивает результат. ChatGPT отвечает за техническую реализацию и предлагает решения.**

Мы не просто пишем код по техническому заданию. Мы совместно развиваем игру, экспериментируем, проверяем идеи и постепенно доводим проект до качественного законченного продукта.

Главный критерий успеха — не количество строк кода и не сложность реализации, а удовольствие от готовой игры.
